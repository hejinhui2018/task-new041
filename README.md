# KioskFlow 展示终端流程验收台

为展馆数字导览团队打造的流程验收工作台：把**页面、停留时长、前置条件、可中断提示**组成一条真实流程，在浏览器本地模拟**触摸、下一步、超时、无障碍暂停、断电恢复**，并验证状态机的关键保证——**同一块屏幕重复触发不会偷偷推进两次，恢复供电也不会绕过必经步骤**。

技术栈：React 18 + TypeScript + Vite，全部在浏览器本地运行，无任何服务端依赖。

## 运行方式

```bash
npm install        # 安装依赖
npm run dev        # 开发模式（默认 http://localhost:5173）
npm test           # 运行全部测试（vitest，33 个用例）
npm run build      # 类型检查 + 生产构建（输出到 dist/）
npm run preview    # 预览生产构建产物
```

## 背景与对应的事故复现

> 事故：工作人员在讲解中途切换展厅，屏幕恢复后跳过了必看的安全提示，现场只能整机重启。

工作台内置「故障注入」按钮，一键复现该现场（讲解中途跳厅 + 跳过安全提示 + 断电）。注入后按「恢复供电」，可以看到系统被**恢复守卫**重定向回必看步骤，并在「恢复前后差异」面板中对比断电时冻结的现场与恢复后的实际状态。

## 内置流程：海岸生态展

三块互动屏（A 迎宾 / B 生态长廊 / C 互动探索），自动播放与人工讲解中途交错：

| # | 页面 | 屏 | 类型 | 停留 | 前置条件 | 记录事实 | 特殊规则 |
|---|------|----|------|------|----------|----------|----------|
| 1 | 欢迎页 | A | 自动播放 | 6s | — | `welcomed` | |
| 2 | 必看安全提示 | A | 自动播放 | 8s | `welcomed` | `safety-viewed` | **必看 · 不可跳过 · 不可中断** |
| 3 | 潮间带生态 | B | 自动播放 | 10s | `safety-viewed` | `tide-introduced` | |
| 4 | 珊瑚与鱼群 | B | 人工讲解 | 手动 | `tide-introduced` | `coral-narrated` | |
| 5 | 触摸池探索 | C | 互动 | 手动 | `coral-narrated` | `touchpool-done` | |
| 6 | 保护行动 | C | 人工讲解 | 手动 | `touchpool-done` | `conservation-narrated` | |
| 7 | 谢幕循环 | A | 自动播放 | 8s | `conservation-narrated` | `loop-ready` | |

## 功能地图（验收对照）

| 需求 | 实现 |
|------|------|
| 模拟触摸 / 下一步 / 超时 / 无障碍暂停 / 断电恢复 | 中栏「操作台」+ 屏上「触摸屏幕」按钮 |
| 记录当前屏幕、已完成事实、被阻断原因 | 右栏「运行状态」面板（含幂等拦截计数） |
| 重复触发不推进两次（幂等） | epoch 令牌丢弃过期定时器回执 + 350ms 推进去抖 + 事实集合语义 |
| 恢复不绕过必经步骤 | 恢复守卫三条：必看重定向 / 必看完整重播 / 前置条件缺失则阻断 |
| 替换一页 | 右栏「替换一页」编辑器（可撤销、随快照持久化） |
| 跳到故障点 | 左栏「故障现场」注入按钮 |
| 恢复前后差异 | 「恢复供电」后自动弹出对照表 |
| 撤销 / 重做 | 顶栏按钮，基于状态快照历史（上限 100 步） |
| 刷新恢复 | 每次状态变化写入 `localStorage`，刷新后从剩余时长继续计时 |
| 重置 | 顶栏「重置流程」（保留页面编辑，可撤销） |

## 架构

```
src/
├── core/                    # 纯函数核心：不依赖 DOM/时钟/存储，时间由参数注入
│   ├── types.ts             #   领域类型（流程定义、运行状态、事件）
│   ├── reducer.ts           #   状态机：所有状态转换的唯一入口 reduce(state, event, now)
│   ├── flow.ts              #   查询助手（前置条件、必经守卫、标签）
│   ├── persistence.ts       #   快照序列化/校验/修复（localStorage）
│   ├── history.ts           #   撤销/重做（快照历史 + 恢复前后对照）
│   ├── coastalFlow.ts       #   内置「海岸生态展」流程
│   └── __tests__/           #   33 个测试用例
├── ui/                      # React 组件（流程图、互动屏、操作台、状态检查器、
│                            #   页面编辑器、恢复差异、事件日志、故障面板）
├── App.tsx                  # 装配：事件派发、定时器调度、持久化副作用
└── main.tsx
```

关键设计：

- **纯函数状态机**：`reduce(state, event, now)` 是唯一转换入口，UI 只是事件的来源与状态的投影，因此全部行为可确定性测试。
- **幂等三重保障**：① 每次进入步骤递增 `epoch`，定时器回执必须携带当时的 epoch，过期回执直接丢弃；② 350ms 内的人工推进（next/touch）视为重复触发；③ 事实记录是集合语义，重复完成为 no-op。被拦截的事件计入 `幂等拦截` 并写日志。
- **计时暂停**：运行中保存绝对截止时间，暂停/断电/刷新时换算回剩余毫秒冻结；恢复时基于当前时间重新武装计时器并递增 epoch，作废旧回执。
- **必经步骤守卫**：进入校验（`resolveEntry`）对跳转、自动推进、供电恢复统一生效——目标之前存在未完成的必看步骤时重定向过去；前置条件缺失则进入阻断态并记录原因。

## 建议的验收动线

1. `npm run dev` 打开页面，观察欢迎页自动倒计时推进；在珊瑚讲解页用「触摸屏幕」与「下一步」交错推进到谢幕。
2. 连点「下一步」或「触摸屏幕」，观察「幂等拦截」计数增长而流程不多走。
3. 在自动播放页按「无障碍暂停」，倒计时冻结；「继续播放」从暂停点恢复。在必看安全提示页暂停会被拒绝。
4. 点击「注入故障现场」→「恢复供电」：流程被守卫回必看安全提示，查看「恢复前后差异」。
5. 在流程图上直接点击后面的页面：前置条件不足会被阻断并显示原因；未看完安全提示时会被重定向回去。
6. 用「替换一页」改某页标题/停留/前置条件（例如把潮间带的前置改成一个不存在的事实，观察自动推进被阻断，再改回来按「下一步」继续）。
7. 随时「撤销/重做」；刷新页面验证状态恢复；「重置流程」从头再来。
